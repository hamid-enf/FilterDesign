# فصل ۱۸ — عیب‌یابی

## مفهوم

پاسخ به رایج‌ترین مشکلات: خطاهای وضعیت، رفتار غیرمنتظره، و مسائل پلتفرمی.

## جدول خطاها

| کد وضعیت | معنی | راه‌حل |
|---|---|---|
| `FCE_ERR_INVALID_ARGUMENT` | آرگومان NULL | spec/result/ws را چک کنید |
| `FCE_ERR_INVALID_SPEC` | مشخصات نامعتبر | fs>0، 0<fc<fs/2، fc2>fc1؛ برای cheby1/ellip حتماً ripple بدهید |
| `FCE_ERR_UNSUPPORTED` | ویژگی در build غیرفعال است | `filtercoeff_config.h` را چک کنید |
| `FCE_ERR_NUMERICAL` | واگرایی عددی، یا مرجع نرمال‌سازی روی صفر فیلتر افتاده | مشخصات افراطی (attenuation>150dB و...) را ملایم کنید؛ اگر مرجع نرمال‌سازی صریح داده‌اید (مثلاً `FCE_NORM_NYQUIST`)، به AUTO یا PASSBAND_PEAK تغییرش دهید |
| `FCE_ERR_UNSTABLE` | طراحی ناپایدار | نباید اتفاق بیفتد؛ report کنید |
| `FCE_ERR_OVERFLOW` | سرریز fixed-point | Q31 یا float استفاده کنید؛ مقیاس را عوض کنید |
| `FCE_ERR_QUANTIZATION` | کمی‌سازی فیلتر را ناپایدار کرد | Q31/float؛ مرتبه یا پهنای باند را تغییر دهید |
| `FCE_ERR_BUFFER_TOO_SMALL` | workspace کم است | از `fce_workspace_required()` استفاده کنید |

## پرسش‌های رایج

### ۱. چرا ضرایب من با MATLAB فرق دارد؟

ترتیب سکشن‌ها و جفت‌کردن قطب/صفر ممکن است متفاوت باشد — اما **پاسخ فرکانسی یکسان است**. اگر MATLAB از فرمت `[b0,b1,b2,1,a1,a2]` استفاده می‌کند، `a0=1` را اضافه کنید.

### ۲. چرا خروجی Q15 من `-32768` ندارد؟

کتابخانه به عمد محدوده را `[-32767, 32767]` نگه می‌دارد تا تقارن Q15 حفظ شود و `-32768` (که معکوسش خارج از محدوده است) تولید نشود.

### ۳. چرا `quant_response_max_error_db` در باند قطع بزرگ است؟

این معیار فقط بالای آستانهٔ −60dB محاسبه می‌شود. اگر می‌خواهید کل باند را ببینید، خودتان با `fce_response_sos()` روی ضرایب بازسازی‌شده اسکن بگیرید.

### ۴. `spec.order = 0` برای Bessel خطا می‌دهد؟

بله — Bessel فرمول بسته‌ای برای مرتبهٔ خودکار ندارد (همان‌طور که `scipy.signal.iirfilter` هم ندارد). مرتبه را دستی بدهید.

### ۵. ضرایبم روی float32 کمی جابه‌جا شده؛ مشکلی هست؟

خیر — گرد کردن نهایی float32 خطای ~6e-8 نسبی دارد. اگر به دقت بیشتری نیاز دارید از `FCE_PRECISION_FLOAT64` استفاده کنید (محاسبات داخلی در هر دو حالت float64 است).

### ۶. روی ESP32-C2 طراحی خیلی طول می‌کشد؟

طبیعی است — بدون FPU، float64 نرم‌افزاری است. ضرایب را روی Host تولید و embed کنید (فصل ۱۶).

### ۷. چرا مرتبهٔ خودکار من با `buttord` یکی نیست (۱ اختلاف)؟

گرد کردن به بالا گاهی در مرزها ۱ اختلاف می‌دهد. هر دو جواب مشخصات را برآورده می‌کنند؛ برای اطمینان، `stopband_atten_measured_db` را ببینید.

### ۸. گزارش می‌گوید `FCE_FLAG_SPEC_MARGINAL`؛ یعنی چه؟

یعنی حاشیهٔ پایداری خیلی کم است (قطب‌ها خیلی نزدیک دایرهٔ واحد) یا مشخصات به‌سختی برآورده می‌شود. برای fixed-point، Q31 یا مرتبهٔ متفاوت را امتحان کنید.

### ۹. چگونه می‌توانم فقط FIR را build کنم؟

```c
/* filtercoeff_config.h */
#define FCE_ENABLE_IIR 0
#define FCE_ENABLE_FIXED_POINT 0
```

### ۱۰. ضرایب من در کتابخانهٔ runtime بی‌ثبات است!

- قرارداد علامت را چک کنید: `y = b0x + b1x + b2x − a1y − a2y` (منهای!)
- مطمئن شوید `a0` را به‌صورت ۱ (نه ۰) به runtime می‌دهید.
- اگر runtime فقط آرایهٔ ۶تایی می‌پذیرد، `{b0,b1,b2,1,a1,a2}` بسازید.

### ۱۱. چرا `FCE_FLAG_SYMMETRY_WARNING` گرفتم؟

دو دلیل ممکن است: (الف) HP/BS با تعداد ضریب زوج خواسته‌اید — فیلتر Type-II حتماً در Nyquist صفر دارد و کتابخانه از قبل اعلامش می‌کند؛ (ب) نرمال‌سازی AUTO روی یک صفرِ ذاتی تقارن افتاده (بالاگذر زوج یا Differentiator فرد در Nyquist) و کتابخانه به‌صورت خودکار به `FCE_NORM_PASSBAND_PEAK` سقوط کرده است. در هر دو حالت طراحی معتبر است؛ فقط `|H|` دقیقاً در فرکانس مرجع قابل نرمال کردن نبوده. اگر خودتان صریحاً آن مرجع را بدهید، `FCE_ERR_NUMERICAL` می‌گیرید.

### ۱۲. چرا `FCE_FLAG_NUMERICAL_WARNING` بعد از نرمال‌سازی ست شده؟

یعنی بهرهٔ مرجعِ انتخاب‌شده آن‌قدر کوچک است که تقسیم بر آن بیش از ~1e8 برابر تقویت می‌کند — نتیجه عملاً نویز عددی است (مثلاً نرمال‌سازی صریح روی فرکانسی عمق در باند قطع). طراحی انجام شده، اما آن خروجی واقعاً «بهرهٔ واحد در آن فرکانس» نیست.

## چک‌لیست نهایی

- [ ] `fce_spec_defaults()` را صدا زده‌اید
- [ ] `fce_workspace_required()` برای اندازهٔ workspace
- [ ] `result.status == FCE_OK`
- [ ] `result.flags` را بررسی کرده‌اید (به‌خصوص بعد از Q15)
- [ ] `result.num_sections` / `result.num_taps` درست است
- [ ] قرارداد علامت با runtime شما یکی است
